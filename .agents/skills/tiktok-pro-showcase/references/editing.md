# สเปกตัดต่อคลิปแนวตั้ง

ใช้สเปกนี้เมื่อทำคลิปเดี่ยวด้วย `tiktok-pro-showcase` ตัวเลขด้านเลย์เอาต์ สี และไฟล์ส่งออกอ้างจากส่วนที่อ่านได้ใน MP4 แนบ ค่าอื่นระบุเป็นจุดเริ่มสำหรับปรับตามฟุตเทจจริง

## อินพุตและไฟล์กลาง

- `Video/` เป็นเสียงหลักและ A-roll รับชื่อ `Video` หรือ `video` ตามโฟลเดอร์ที่มีอยู่ `Insert/` เป็น B-roll ภาพนิ่ง วิดีโอแทรก และเสียงประกอบ `Output/` เป็นไฟล์พร้อมส่ง เลือกโฟลเดอร์ที่ตรงกับ manifest เมื่อมีชื่อหลายแบบ
- `.work/tiktok_pro/<clip_id>/` เก็บไฟล์กลาง พรีวิว และผลตรวจ เริ่มจาก `clip_id`, `mode`, `source`, `source_start_s`, `source_end_s`, `script_path`, `asset_index`, `preset_version`
- ใน EDL จด `start_s`, `end_s`, `asset_id`, `src_in_s`, `layout`, `overlay_text`, `sfx` ต่อช็อต เมื่อใช้ Split Screen ให้บันทึก asset และช่วงเวลาของทั้งสองช่อง ตั้ง timestamps จากเสียงหลังตัด
- โหมดเสียงจริงหน้ากล้องมีเทคหลักเป็นภาพและเสียง โหมด VO ใช้ไฟล์เสียงเป็นหลัก เมื่อไม่มีภาพที่ตรงคำพูดให้สลับเป็นช็อตสินค้าหรือมือที่ตรวจได้

## เสียงและการแมปเวลา

1. วัดช่วงเสียงจริงด้วย `ffprobe` หรือ `probe.py` ถอดไทยด้วย word timestamps ถ้าทำได้ เก็บคำดิบและช่วง `start_s`/`end_s` ค่ามิลลิวินาทีเป็นหน่วยบันทึก ใช้การฟังและ alignment ประเมินความแม่นยำ
2. ตรวจ dead air จาก waveform, `silence.py` หรือ `silencedetect` เริ่มลอง threshold `-40 dB` และช่วงนิ่ง `0.30 s` แล้วปรับตาม noise floor รักษาจังหวะเน้น เว้นระหว่างประโยค และหัวท้ายพยางค์ เก็บช่วงที่ใช้แบบ `{src_start_s,src_end_s,out_start_s}`
3. กรณี VO แบบเสียงล้วน ให้ใช้ crossfade สั้นราว 10–30 ms ที่รอยต่อถ้าจำเป็น เมื่อเป็นปากคนพูดตัดภาพกับเสียงจากชุดช่วงเดียวกัน ถ้าจะซ้อนเสียงด้วย crossfade ให้ใส่ตรงรอยต่อที่ปิดด้วย B-roll หรือคุมช่วงซ้อนให้สมการเวลาสะท้อนจริง
4. แปลงเวลาที่อยู่ในช่วงที่เก็บด้วย `t_out = out_start + (t_src - src_start)` ถ้ามี crossfade ให้ลด `out_start` ของช่วงถัดไปตามเวลาซ้อนจริง ฟังรอยต่อและสร้างซับบน clock ใหม่ วิธีที่ง่ายเมื่อเวลาไทยคลาดเคลื่อนคือถอดซ้ำจาก `voice-clean.wav` แล้วตรวจชื่อแบรนด์ ราคา และหน่วยกับบท
5. เก็บ `words.json` และ `captions.srt` บน clock ใหม่ ซับข้อความตามเสียงจริง ส่วน Super Text เลือกจาก `overlay_text` ใน beat ให้สั้นและสอดคล้องกับสิ่งที่กำลังพูด Normalize ความดังของเสียงหลักตามพรีเซ็ตและเก็บ headroom ให้เพลงกับ SFX

## เลย์เอาต์ A, B และ D

| เลย์เอาต์ | การวางช็อต |
| --- | --- |
| **A · Hero Hook Cut** | เปิดช่วง 0–3 วินาที ใช้ช็อตที่สื่อคำเปิดทันที ประมาณ 0.8–1.2 วินาทีต่อช็อต ตัวอย่างคือ ช็อตเปิดปัญหา → เห็นสินค้า → เห็นสาธิตชัด ๆ |
| **B · Split-Screen Before/After** | พื้นหลังเบลอเต็ม 9:16 ซ้อนกรอบแนวนอนสองช่องบน–ล่าง ป้ายกำกับด้านล่างของแต่ละช่อง ใช้ White Flash สั้นก่อนเข้าฉากเมื่อเหมาะ ภาพ Before/After ต้องเทียบได้จริง ใช้ป้ายสถานการณ์ตามที่เห็นในภาพ |
| **D · Clean Full-Screen / Letterbox** | ปล่อยช็อตแนวตั้งเต็มถ้าตัดแล้ววัตถุยังครบ ถ้าเป็นภาพแนวนอนให้รักษากรอบและเติมพื้นหลังเบลอ 9:16 ใช้ Smooth Zoom แบบนุ่มนวลเมื่อภาพนิ่งหรือช็อตค้าง |

ให้เลย์เอาต์เปลี่ยนตามบทและหลักฐาน หลีกเลี่ยงการใช้ฟอร์แมตเดิมยาวตลอดคลิป และใช้ช่องภาพเท่าที่เรื่องต้องการ In/Out point ต้องอยู่ในช่วงไฟล์และมีภาพปิดตรง CTA

## Super Text และมิกซ์เสียง

- วางคำสำคัญต่อเนื่องตามประโยคหรือ beat โดยมากหนึ่งบรรทัด ไม่เกินประมาณ 5 คำแบบแบ่งด้วยขอบเขตวลีภาษาไทย ใช้ฟอนต์ Sans Serif ExtraBold ที่แสดงวรรณยุกต์ครบ สี `#00E5FF` สลับ `#FFFFFF` ขอบ `#000000` หนาและมี Drop Shadow
- Pop-up Bounce จาก `0% → 115% → 100%` ที่จังหวะเข้า เคลื่อนไหวสั้นพอให้คนมีเวลาอ่าน ตัวเลือกคือ ASS ที่รองรับ shaping หรือลำดับเฟรม RGBA จากเรนเดอร์ข้อความที่รองรับไทย แล้วซ้อน overlay ตรวจตำแหน่งหลังซ้อนจริงและตอน scale ขึ้น 115%
- จุดเริ่มทดสอบ safe zone บนภาพ 1080×1920 คือกล่อง `x=80..900, y=200..1510` ปรับตาม UI และตำแหน่งตะกร้าบนมือถือ พรีวิวหน้าปกและโพสต์จริงอาจใช้พื้นที่ต่างกัน
- วาง Whoosh ที่ White Flash หรือการเปลี่ยน Layout และ Pop/Click ตรง onset ของ Super Text เริ่ม Pop/Click ที่ 20% และ BGM ที่ 15% ของ gain ต้นฉบับ ลดลงถ้าเบียดคำพูด ไฟล์เสียงที่บันทึกมาดังต่างกันจึงต้องวัดและฟังหลังผสม
- ถ้าผสมเองให้ใช้ `amix` แบบ `normalize=0` ตามที่เห็นในคลิปเมื่อควบคุม gain แล้ว ป้องกัน clipping ด้วย headroom และตรวจ peak หลัง mix ใช้ whoosh/click ที่มีสิทธิ์หรือเสียงที่สร้างสำหรับโปรเจกต์เมื่อมีไฟล์หลักไม่ครบ พรีเซ็ตเริ่มต้นสำหรับงานนี้ใช้ประมาณ `-14 LUFS` และ true peak ไม่เกิน `-1 dBTP` แล้วปรับกับเสียงจริง [FFmpeg audio filters](https://ffmpeg.org/ffmpeg-filters.html)

ตัวอย่างทำพรีวิว Pop ด้วยซับที่ตรวจและจับเวลาจากเสียงหลังตัดแล้ว ใช้ช่องว่างแบ่งวลีไทยเมื่อเครื่องมือแจ้ง `broken_inside_word` แล้วดูตำแหน่งจริงใน contact sheet หากต้องการเปลี่ยนสีและกำหนดสเกลต่อ cue ตามสเปกเต็ม ให้สร้าง ASS ของงานและใช้ `--ass` ส่งเข้า `caption` โดยตรง

```powershell
.\scripts\ffmpeg-tool.ps1 caption '.work/tiktok_pro/P01-01/picture-with-voice.mp4' `
  --srt '.work/tiktok_pro/P01-01/captions.srt' --language th --font 'Noto Sans Thai' --fonts-dir 'assets/fonts/NotoSansThai' `
  --bold --platform tiktok --margin 66 --size 12 --animate pop --color 00E5FF --outline 2 --shadow 2 `
  -o '.work/tiktok_pro/P01-01/caption-preview.mp4' --json
```

## เชื่อมกับ ffmpeg-skill ที่ติดตั้งใน workspace

อ่าน [สกิล FFmpeg](../../ffmpeg-skill/SKILL.md) สำหรับตัวเลือกแบบเต็ม ใช้ [คำสั่งเริ่มต้นในคู่มือ](../../../../WORKFLOW.md#ffmpeg-skill-บน-windows) เมื่อต้องเรียก tool จาก PowerShell สคริปต์จัด compositing แยกตามช็อตตามที่ EDL ต้องการ แล้วประกอบเข้ากับเสียงและซับ

| ขั้น | เครื่องมือในสกิล |
| --- | --- |
| ตรวจสื่อและช่วงเวลาจริง | `probe.py`, `silence.py` สำหรับวัดช่วงเงียบ `cut.py` สำหรับช่วงที่เลือก |
| ถอดเสียงและซับไทย | `caption.py --transcribe --language th` เมื่อมี ASR ที่รองรับ หรือ `caption.py --srt` เมื่อมีซับที่ซิงก์แล้ว |
| วางภาพแทรกและกรอบ | `broll.py`, `insert.py`, `grid.py`, `overlay.py`, `graphics.py` ตามชนิดช็อต สำหรับเลย์เอาต์ที่รวม blur, flash และ text bounce หลายชั้น ให้ประกอบเป็นช็อตกลางหรือใช้โปรแกรมตัดต่อที่ทำพรีเซ็ตนี้ได้ แล้วส่งเข้า timeline |
| รวมและส่งงาน | `render.py` รองรับโปรเจกต์หลายขั้นและ cache สำหรับพรีเซ็ตนี้ให้ส่งออกด้วย `fit.py --fps 60` หรือ FFmpeg ด้านล่าง โปรไฟล์ `export.py --preset tiktok` ของเวอร์ชัน 4.7.1 จะคอนฟอร์มไฟล์ปลายทางเป็น 30 fps |
| ตรวจสิ่งที่เรนเดอร์ | `look.py` สร้าง contact sheet และ `probe.py`/`check.py` วัดข้อมูลปลายทาง เกณฑ์ตัดสินใช้สเปกด้านล่าง |

## พรีวิวและส่งออก

1. สร้าง contact sheet ให้ครอบคลุมต้น กลาง ท้าย รวมเฟรมที่เปลี่ยนเลย์เอาต์ ซับซ้อน และช็อตฉลาก ตรวจความสวยงาม ตำแหน่งข้อความ และการบัง UI จากภาพจริงก่อนเรนเดอร์เต็ม ใช้พรีวิวเคลื่อนไหวและฟังเสียงด้วยเมื่อแก้รอยต่อหรือมิกซ์ เมื่อโจทย์กำหนดพรีวิวให้ผู้ใช้ยืนยัน ให้พักที่ไฟล์พรีวิวตามที่ขอ
2. ส่งออก `Output/<clip_id>_pro.mp4` หรือ `<ชื่อไฟล์ต้นฉบับ>_pro.mp4` เมื่อทำคลิปเดี่ยวที่ไม่มีรหัส ขนาด 1080×1920, CFR 60 fps, H.264, `yuv420p`, AAC 48 kHz ค่าเริ่มต้น CRF 18–20 และ AAC 192 kbps ตามคุณภาพต้นทาง งานที่ถ่ายมา 30 fps สามารถคอนฟอร์มเป็น 60 fps ได้ โดยภาพต้นฉบับยังมีรายละเอียดการเคลื่อนไหวเท่าเดิม
3. ตัวอย่างส่งออกด้วย FFmpeg ตรงเมื่อ `master.mov` เป็นมาสเตอร์แนวตั้งที่จัดภาพ ซับ และมิกซ์ครบแล้ว ใช้ไฟล์ staging ในโฟลเดอร์เดียวกับปลายทางในงานอัตโนมัติ แล้วเผยผลจาก staging เมื่อผ่าน QA

```powershell
ffmpeg -n -i '.work/tiktok_pro/P01-01/master.mov' -map '0:v:0' -map '0:a:0' `
  -vf 'scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=60' `
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p `
  -c:a aac -b:a 192k -ar 48000 -movflags +faststart 'Output/P01-01_pro.mp4'
ffprobe -v error -show_entries 'stream=codec_type,codec_name,width,height,avg_frame_rate,pix_fmt,sample_rate:format=duration' `
  -of json 'Output/P01-01_pro.mp4'
ffmpeg -hide_banner -v error -xerror -i 'Output/P01-01_pro.mp4' -f null -
```

4. ตรวจว่าทั้งเสียงและภาพมีอยู่และไฟล์ decode ได้ ความยาวเท่ากับ EDL ภายในค่าคลาดเคลื่อนที่ประกาศตามเฟรมหรือ codec แล้วเก็บผล `qa.json` บันทึกคลิปที่ผ่านใน `batch-report.csv` งานที่ยังตรวจได้ไม่ครบใช้สถานะ preview หรือ needs_fix ตามกรณี
